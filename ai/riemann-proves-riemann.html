Riemann proves Riemann?

A step-by-step walk through J. L. Nielsen's critique (25 Nov 2026) of Alpöge's Lean proof of the Riemann Hypothesis. Every step in the diagram is a section below, with the Lean source behind it. (YouTube video)

DiagramSummaryWhat the proof claimsWhat the code doesMain routeGlossary

This scaffolding does not reduce the proof to a tautology. Nielsen's findings about the code are correct: the geometric object is an empty shell, and its height is a pasted zeta formula. But take both away and what remains is a real inequality between different quantities, μ + P − Fo ≤ MAIN + error, which roughly 40 analytic estimates have to prove.

And they do. Every independent kernel check accepts the proof, and the Lean FRO and the Mathlib Initiative have certified both the statement and the proof. So the geometry is decoration, and the Riemann Hypothesis may well have been proven by mathematical analysis alone, by a route nobody has explained yet.

    Summary

    Alpöge published a program in Lean, a language where a computer checks every step of a proof. The plan: build a geometric object and measure a number from it, its “height”1, hand that number to a check2 against two limits that come from the zeta-function side3. If the measured number always fits, zeta can have no zeros off the critical line, which is exactly the Riemann Hypothesis (RH). The program ends there, and Lean accepts it.4

    Nielsen says the program never does the measuring: the geometric object is empty, the check meant to confirm it answers “yes” to anything, and the height starts at zero✕. Instead, the program takes a formula from the zeta side, pastes it into the height field, and confirms the height field matches the formula, which of course it does1. That pasted number is what goes into the check2, where it meets limits from the same zeta side3. So the key comparison sets the zeta side against itself, and the whole proof rests on that copy: Riemann proves Riemann.4 All of this sits on the proof’s main route, which the source confirms step by step.

    What the code does · step 4

    Zeta formula vs zeta limits: Riemann proves Riemann

    The comparison

    Put sections 1–3 together. With h = hExpl6, the check reads P ≤ hExpl6 and μ + hExpl6 − Fo ≤ MAIN + error. Cancel the middle term and what is left is μ + P − Fo ≤ MAIN + error: zeta-side quantities on both sides. Nothing independent is squeezed.

    This then flows through the same route as claim 4 to RiemannHypothesis. In Nielsen's words, the formal comparison is “Riemann to Riemann”.

    Claim 3's picture again; every part is now zeta-side.

    Nielsen's toy version

    A 30-line program with the same pattern: a geometry check that is always true, a height set to the target number, and an equation closed by rfl. Lean accepts it with no extra axioms.

    Note the highlighted hRH: the toy theorem takes RH as an input and hands it back. It shows the copy pattern; it is not a fake proof of RH built from nothing.

    from the paperNielsen, Appendix A, pages 16–17 (not in the repository) 
    import Mathlib.NumberTheory.LSeries.RiemannZeta

def anyGeometry : ∀ (_ : Nat), Prop := fun _ => True
def targetFormula : Nat := 42

structure DegenerateModel where
  vol : Nat := 0
  height : Nat
  h_eq : height = targetFormula

structure Bundle where
  geoOk : anyGeometry 0
  model : DegenerateModel

def buildBundle : Bundle :=
  { geoOk := trivial
    model :=
      { vol := 0
        height := 42          -- <-- the assignment (chop this out)
        h_eq := rfl } }       -- <-- closes by definition

private lemma valid_bundle_of_manufactured (b : Bundle) :
    anyGeometry 0 ∧ b.model.height = targetFormula :=
  ⟨b.geoOk, b.model.h_eq⟩

theorem claimed_rh (hRH : RiemannHypothesis) :
    (∃ b : Bundle, anyGeometry 0 ∧ b.model.height = targetFormula) ∧ RiemannHypothesis := by
  let b := buildBundle
  exact ⟨⟨b, valid_bundle_of_manufactured b⟩, hRH⟩

#print axioms claimed_rh

    Glossary

    Lean terms and the names used on this page

    Lean basics

    Lean
    A programming language for writing mathematical proofs that a computer checks step by step.
    Lean accepts
    Lean's kernel, its small checking core, found no step that fails to follow. It checks that the steps fit together, not what the names mean.
    Mathlib
    Lean's standard library of mathematics. It holds the official statement RiemannHypothesis that the program proves.
    RH
    The Riemann Hypothesis: every non-trivial zero of the zeta function ζ has real part ½, so it lies on the critical line.
    Dirichlet L-function
    A family of functions that generalise ζ, one for each character χ. At modulus one the L-function is ζ itself. EveryCharacter says none of them has a zero with real part above ½.
    rfl
    “Equal by definition.” Proves an equation when both sides unfold to the same expression.
    True, trivial
    True is the statement that always holds, and trivial is its proof. A check defined as True passes for any input.
    sorry, axiom
    A sorry is a placeholder for a missing proof; an axiom is a statement accepted without proof. The code uses neither, beyond Lean's three standard axioms.
    commit
    A saved version of the code, named by a hash such as 712a6aef. Every code link on this page points to that version.

    Names used on this page

    geometric object
    What the proof should measure: a variety with sections, volumes and positivity properties. In the code: a “divisor datum”, of type DivX D.
    height h, height field
    The number the proof should measure from the geometric object, one real number per word u. It is stored in the height field div.h.
    zeta side
    Everything built from the analytic formulas for ζ and the L-functions. The code calls it the “row side”.
    zeta formula hExpl6
    The zeta-side formula that the code writes into the height field.
    the check (WordFacts)
    The condition that the height lies between a lower and an upper limit, for every word u.
    lower and upper limit
    Lower: a pairing height P, built from Bk, must be at most h. Upper: μ + h − Fo must be at most MAIN + error. Both are zeta-side.
    geometry check
    The test that the geometric object is real. geoOf is a real one; anyGeometry always returns True. GeoCl wraps either.
    certificate
    The proof that a geometry check passed. With anyGeometry it is just trivial.
    setDiv
    Rebuilds a geometric object with a new value in its height field.
    measuring lemmas
    Six lemmas written to get geometric facts out of the object, listed in section 1. None is ever used.
    removal test
    Nielsen's experiment: take out one part and see whether the program still compiles.
